# AI絵 → SVG 変換

## 原則

- 意味的な簡略化（描き直し）は**画像生成モデル**の仕事。画力が要る工程をエージェントが代行しない。
- エージェントがSVGパスを**手書きしない**。座標の当てずっぽうで品質が崖落ちする（実証済み）。
  エージェントの仕事は分解・予算設定・プロンプト・計測・合否判定。
- トレースは**フラット化した絵にだけ**かける。slop絵への直接トレースは細線がパスとして
  生き残り、巨大で編集不能なSVGになる（実測：376パス/819KB vs 描き直し後 104パス/167KB）。

## 適用範囲（実測で判明）

- **強い対象：質感過剰な絵**。髪の細線、グラデーション、発光、実写の質感など、
  「1つの物体の中の線と質感」が支配的な絵。描き直しでパス数は半分以下になる。
  実測：アイコン絵 376→104パス、円形アバター 241→84パス、横長の複雑な絵 503→221パス。
- **弱い対象：要素過密な画面**。人物が何人もいる、帯状の背景、文字群、UI部品など、
  パス数が「物体の個数」で決まる絵。描き直してもパス数はほぼ減らない。
  実測：パチンコのフィーバー画面（人物5人＋玉5個＋ロゴ群）482→468パス
  （バイト数は 768→571KB と減るが、パス数は不変）。
  この手の対象に効くのは質感の簡略化ではなく、要素自体を減らす／統合する別の分解であり、
  本スキルの範囲外。着手前に「質感型か、要素数型か」を見分けること。
- **弱い対象：光学現象型**。透明・虹色・ボケそのものが主題の絵（シャボン玉の中の風景など）。
  透明感はベクターに翻訳できないため、描き直しは中身を記号化（ピクトグラム化）するしかない。
  階調モード（後述）で「段になったベタ面＋ステンドグラス方式（重なりを実色の面で置く）」に
  すれば情報は残せるが、質感そのものは戻らない。元絵が柔らかいグラデ主体だと直接トレース
  自体が安く、旨味も小さい。実測：泡の少女 直接134パス→フラット版68パス（ただし記号化）、
  階調版177パス。
- **抽象化済みの絵**：描き直しは簡略化ではなく「清書」として働く。パス数の減りは小さいが、
  JPEGノイズと線の震えが消えてバイト数は大きく減る。実測：ちびキャラ 154パス/279KB →
  125パス/159KB。この場合、元絵の抽象度（鼻・口なし等）は厳密に保持し、パーツを足さない。

## 工程

### 1. 分解（先に決める）

元絵を見て、次を列挙してから生成に入る。

- **保持する特徴**：キャラの本人性を担う要素（髪型のシルエット、目の特徴、代表色、
  アクセサリ、ポーズ、構図）。欲張らない。部品だけでなく次も含める：
  - **表情の癖**：視線の伏せ具合、笑いの非対称さ、首の角度など。無指定だとモデルの
    「量産型の可愛い」に平均化され、パーツが全部残っても性格だけ抜ける（実証済み）。
  - **目の開き具合**：虹彩の見える割合（％）で測る。目の「枠」の大きさが同じでも、
    横長・半開き→丸・全開に変わると印象が別物になる（実測：枠比 0.55→0.51 と
    ほぼ不変でも全開化で別人化）。
  - **構図のはみ出し**：髪や体がフレーム端で切れている構図は、切れたまま保持すると
    明示する。無指定だとモデルが被写体全体を画面内に収め直す（実証済み）。
- **捨てるディテール**：髪の細線・毛束内部の線、グラデーション、発光、キラキラ、
  微細パターン（回路・レース・反射）、透かし・文字。
- **部位ごとの参照モード**：保持と簡略化はトレードオフなので部位で分ける。
  - 顔・目・特徴アクセサリ：元絵をそのまま参照（コピー寄り）
  - 髪の内部・服のシワ・背景：シルエットと色だけ参照し、中身は新規に描かせる

### 2. 描き直し（画像生成）

`references/redraw-prompt.md` のテンプレートを使い、元絵を添付して画像生成する。
要点は「簡略に」という形容詞ではなく、**部位ごとの数値予算**で指定すること：

- 髪：大きな房のみ（合計7房程度まで）、内部に線ゼロ、飛び出し毛なし
- ハイライト：太い帯1本だけ。筋状にしない
- 塗り：フラット＋影1色まで。グラデなし
- 背景モチーフ：大きな形を数個まで（雷、回路ライン等）
- 鼻：**点1個は必須**。線や形は要らないが、ゼロだと顔の中心が浮く（実証済み）。
  色は**肌の影色系で低彩度**に指定する。ピンクや赤で置くと「赤鼻」という別の記号に
  化ける（実証済み）。
- 目の開き具合：**虹彩の露出割合を％で指定**する（例：85%＝ほぼ全開、70%＝半開きで
  生きてる目）。「半目で」等の形容詞だけだと全開⇔スリット状の両端に振れる（実証済み）。
- 構図・色・ポーズは元絵を保持する。フレーム端で切れている要素は切れたままに。

生成後は目視ゲート（下記）を通し、ダメなら部位指定を強めて再生成する。

#### 抽象度ダイヤル（部位ごとに設定する）

抽象度は一律ではなく部位ごとのダイヤル。全体の目安は3段階：

- **強**（階調2〜3、房少なめ）：アイコン・小サイズ用途向け。完成度の高い原画では
  「味」まで削れて記号化する。実測：魔女っ子 65パス/100KB（絵としては原画以下）。
- **中**（階調4前後、顔はコピー寄り、背景は強め）：スイートスポット。質を保ったまま
  パス数は半分以下になる。実測：サイバー娘 469→210パス。
- **弱**（階調6、線と描き込み保持）：硬いエッジの階調が全面に残るため段の数だけ
  パスになり、**元絵の直接トレースより重くなる**ことがある（実測：魔女っ子
  弱 412パス/741KB vs 直接 162パス/305KB）。SVG化の旨味が反転するので避ける。

部位別の配分の原則：**本人性の核（目など）だけ高予算、他は中予算、背景は低予算**。
実測：アイコンで目だけ高予算にしたら、前回とほぼ同コスト（103パス）で目の情報量だけ上がった。

#### 階調モード（濃淡が要る絵向け）

「グラデ禁止・ベタのみ」だと濃淡が買えない絵（透明・光・柔らかい陰影が主題）では、
部位ごとに**階調数**を指定し、段になったベタ面で濃淡を作る（例：髪4階調・肌3階調・
泡の内部8階調）。透明感は**ステンドグラス方式**（重なる部分を半透明ではなく実色の面で
置く）で表現する。代金はパス数 約2.6倍（実測：泡の少女 フラット68パス→階調版177パス）。

#### トレース閾値を前提に描く

描き直した絵は固定設定でトレースされる。トレーサに殺される描き方を避ける：

- **顔パーツは大きく・太く・濃く描く**。「subtle / 薄く優しく」は地雷（下記の死因参照）。
  繊細さが要るなら、トレース後にSVG側で弱める方が安全。
- **肌と髪の明度を寄せない**：明度がほぼ同じで色味だけ違う色同士（薄ピーチ肌と白髪など）は
  トレーサが同一レイヤーに統合し、平均色（灰白）に潰れる。実測：肌 (247,230,220) と
  髪 (239,241,247) が統合され顔が白化した。肌は髪より明確に暖かく・濃く描く。

### 3. トレース（機械処理）

同梱スクリプトで固定設定トレース＋計測する：

```bash
pip install vtracer pillow cairosvg   # cairosvg はプレビュー描画用（任意）
python3 scripts/trace_and_measure.py input.png output.svg --render preview.png
```

固定設定（比較可能性のため変えない）：`filter_speckle=16, color_precision=5,
layer_difference=24, corner_threshold=60, length_threshold=6.0, splice_threshold=45,
path_precision=2, mode=spline, colormode=color`

#### トレースで顔パーツが死ぬ2つの死因

- **色統合**（layer_difference）：広くて薄いもの（チーク、肌の階調）が近接色レイヤーに
  統合されて消える。対策は描き直し側のコントラスト。
- **スペックル除去**（filter_speckle=16）：小さくて細いもの（鼻の点、口の細線）が
  ノイズとして捨てられる。対策は大きく・太く描くこと。それでも死んだ必須パーツは
  工程5でSVG側に足す。

### 4. 検証ゲート

- **目視（描き直しラスター）**：次を確認する。
  - 髪の内部線がゼロ（房の境界線のみ）になっているか
  - 保持する特徴が全部残っているか（特に目の特徴、鼻の点）
  - 構図と色が元絵から崩れていないか
- **目視（SVGレンダリング）【必須】**：トレース後のSVGを実際に描画（cairosvg等）して
  確認する。**ラスターだけ見て合格にしてはいけない**。固定設定トレースで顔が崩壊した
  事故の実例あり（チーク・鼻・口が消え、文字が食われた）。確認点はラスターと同じ
  （顔パーツの生存、肌色の分離、文字の欠け）。
- **計測**：元絵の直接トレースと描き直し後トレースで、パス数とSVGバイト数を比較して報告する。
  目安はパス数で半分以下。届かない場合は描き直しの予算指定が弱いので工程2へ戻る。
  ただし元絵が低解像度・元々フラットな絵では逆転することがある（実測：ミーム絵
  直接31パス→描き直し後77パス）。その場合の旨味はサイズではなく解像度と編集可能性。

### 5. SVG側の調整（トレース後）

生成モデルは形容詞の指示で両端に振れる（薄すぎ⇔濃すぎ）。数値で決められる調整は
再生成せずSVG側でやる：

- **色の置換**：肌色などの fill 値を目標RGBへ直接置換する。一発で中間に着地する
  （実測：肌 (250,201,184)→(249,218,196) に置換、パス数・サイズ不変）。
- **小パーツの後足し**：鼻の点など「小さくて必ず要るパーツ」は、元絵の実測座標に
  楕円等で足す。トレースに任せるとスペックル除去で確実に死ぬ（実証済み）。
- **トーンパターン**：影色のベタ面を `<pattern>` のドット塗りに差し替えると、
  パス数ゼロ増（defs 1個、約+260バイト）で濃淡を足せる。濃さはドット密度の
  パラメータで持てる。

## 落とし穴（実測済み）

- **白黒化を勝手に前提にしない**：「漫画風」は線と塗りの経済性を借りる意味であり、
  色を捨てる指示ではない。ユーザーが言っていない前提を足さない。
- **「simple / minimal」の形容詞だけでは効かない**：モデルの視覚priorが勝って
  ディテールを足す。カテゴリ変換（髪→大きな房の集合）と数値予算で縛る。
- **キラキラは形を変えて残留する**：フラットな星形などになって残ることがある。
  完全に消すなら予算で「装飾モチーフは◯個まで」と数える。
- **頭ごと回転させるな**（手書き・編集時）：パーツを個別に実測座標へ置く方が崩れない。
- **モデルの「標準形」prior**：無指定の部分はモデルの標準形に寄る。実測で確認した4種：
  ①目の全開化（半開き→丸く全開）②表情の平均化（癖のある笑い→量産型の可愛い）
  ③構図の完全形化（フレームで切れた髪→全体を画面内に収める）④色の極端化
  （薄く⇔濃くの両端）。対策は全部同じで、保持したい性質を数値・禁止事項で指定する。
- **形容詞は両端に振れる**：「半目で」「濃く」だけでは着地点が定まらない。
  虹彩の露出％、RGB値、房の数など、測れる単位で指定する。
- **全体一括のトーン後処理は顔を殺す**：ラスター全体を量子化（ポスタリゼーション）
  すると、面積の小さい顔に色数が回らず肌・頬・目の境界が潰れる（実測：パス数も
  134→304に爆発）。階調分離は後処理ではなく描き直し工程で入れる。やむを得ず
  後処理する場合は顔だけ専用パレットにするか、顔を処理から除外する。
- **顔パーツの保持は描き直し工程の仕事**：元絵で低コントラストに描かれた鼻・口は、
  後処理（エッジ検出＋インク補強でも）では復元できない。無い線は処理では作れない。
  モデルが線として明示的に描き直すルートでのみ残る。
- **トレース後のSVGはまだアンカー羅列**：コードベースへの組み込み（部品化・名前付け）は
  別工程。本スキルの到達点は「トレース可能なフラット絵」と「計測済みSVG」まで。
