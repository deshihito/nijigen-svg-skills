# AI絵 → SVG 変換

AI絵をSVGにする作業は、3つの異なる変換の連鎖である。各変換には「得意な
正確さ」があり、概念を理解していれば個別ケースへの対処はそこから導ける。

## 概念

### 1. 描き直しは編集ではなく再生成である

画像モデルは元の絵を加工しない。様式カテゴリと題材から、絵を毎回新しく
生成する。したがって：

- **無指定の次元は、様式カテゴリの標準形で埋まる**。目の開き具合、表情の癖、
  構図の収まり、色の濃さなど、固定しなかった性質はすべて「その様式で
  ありふれた形」に置き換わる。保持したい性質は、例外なく明示的に固定する。
- **様式は連続量ではなくカテゴリである**。簡略化の指示を強めていくと、
  ある点で様式そのものが切り替わり（イラスト→マスコット等）、形の文法が
  別物になる。抽象度は「量」であると同時に「どの様式に居るか」の選択である。
- **形容詞は拘束力を持たない**。「simple」「優しく」「半分くらい」は測定
  できないため、モデルの標準形に負ける。拘束は測定できる単位でのみ効く：
  個数、割合（％）、色値、階調数。
- **生成の精度は毎回ブレる**。同じ指示でも従う回と従わない回があり、
  色は色相ごと偏る。ブレは生成段に閉じ込め、後段は決定的に保つのが
  設計原則：ゲートで検出し、局所の修正生成とコード側の決定的処理
  （色の数値置換、パーツの後足し）で吸収する。色や位置のずれを
  再生成で直そうとしない。

### 2. 情報はチャネルに分かれて宿る

絵の情報は独立したチャネルに分散している：輪郭（シルエット）、内部の線、
階調の段差、色、文字。各チャネルは異なる工程で生き、異なる仕組みで死ぬ。

- 本人性がどのチャネルに符号化されているかは絵によって違う。変換で
  チャネルを1つ消すと、そのチャネルにしか無い情報は一緒に消える。
  着手前に「この絵の本人性はどこにあるか」を見極めることが、抽象度の
  下限を決める。
- **文字は図形ではなく記号列である**。文字の情報は字形のパスではなく
  文字列そのものに宿る。だから文字はトレースせず、テキストとして持つ
  （工程5）。パス化した文字は劣化し、文字列として持てば劣化しない。
- **環境光は色チャネルに混ざって記録される**。色付きの照明で照らされた
  肌は「肌色＋照明色」として描かれるため、直接トレースでは照明色の
  泥になる。描き直しの段階で、照明を通常の局所色（通常の肌色など）へ
  翻訳してから変換する。
- **密度そのもの・質感そのものが内容の絵**では、変換で本体が消える。
  残るのは構図・シルエット・情報設計までであり、それは「変換」では
  なく「別作品として描き直す」判断になる。

### 3. コストは「要素数 × 要素あたりの境界の複雑さ」で決まる

SVGのパス数とサイズは、ほぼこの積で決まる。簡略化が効くのは、要素の
内部の複雑さ（細線、質感、階調）が支配項のときだけ。要素の個数そのものが
支配項なら、内部をいくら簡略化しても総量は減らない。その場合は要素を
減らす・統合するという別の操作が要り、それはこのスキルの対象外である。
着手前に、どちらの項が支配的かを見分ける。

### 4. 予算は全体ではなく部位へ配分する

総コストは部位ごとのコストの和である。一律の簡略化は、本人性を担う部位を
飢えさせ、どうでもいい部位に浪費する。配分の原則は1つだけ：
**本人性を担う部位に予算を集中し、残りから削る**。予算の指定は概念1の
通り、測定できる単位（房の数、階調数、露出の割合）で書く。

### 5. 下流の閾値が、上流の描き方を決める

機械トレースには閾値がある：近い色は統合され、小さい領域は捨てられる。
閾値より下に描かれたものは、どれだけ上手く描いても残らない。したがって
残したいものは閾値より大きく・濃く描き、繊細な調整は変換後に行う。
また色は絶対値ではなく**隣接する部位との関係**で知覚され、統合される。
分離したい部位同士は、明度差を確保する。逆に言えば、印象のずれは
単独の色ではなく部位間の関係のずれとして現れる。

- **固定設定は常に安全側ではない**。近接した色同士の距離が統合閾値の
  際どい所にある絵では、固定設定が全面崩壊を起こす（軽い＝成功では
  ない）。崩壊したら設定を厳しくして再トレースする（color_precisionを
  上げ、layer_differenceとfilter_speckleを下げる）。
- **同色の隣接領域は1つのレイヤーに統合され、境界を越えて氾濫する**
  ことがある。線で分離されていても起きる（古典セル画でも起きる）。
- 復旧の定石は**領域別の重ね合わせ**：落ちた部位だけを緩い設定で
  再トレースし、「特徴色＋小面積」のパスだけ抽出して重ねる。切り出し
  領域の大半を覆う全面レイヤーパスは背景ごと持ち込んで矩形に蓋を
  するため、必ず除外する。

### 6. 検証は最終形で行う

合格は変換をまたいで持ち越せない。中間生成物が良くても、次の変換で
情報が落ちれば最終形は壊れている。各工程の出力は、それを受け取る側が
実際に見る形（レンダリング画像）で目視し、数値（パス数・サイズ）で
計測して初めて判定する。

### 7. 正確さの種類で担い手を分ける

- **意味の判断**（何を残し、何を捨てるか／どう描くか）→ 画像モデル
- **機械的な変換**（輪郭のパス化）→ トレーサ
- **数値の正確さ**（色値、小さいが必須のパーツ、文字列）→ コード

数値で決められることを生成に頼むと両端に振れ、文字列をパス化すると
劣化し、パスを手で書くと品質が落ちる。エージェント自身の仕事は、
分解・配分・指示・計測・判定という指揮側であり、描画そのものではない。

### 8. 目標の塗りは「影を形で描く」文法である

簡略化の目標は「フラットであること」そのものではなく、次の文法で
塗られた状態である：

- **線が境界を決め、塗りは面を埋める**。境界が線に担われている絵は、
  ベタ面が滲まず、トレースしても境界がそのままパスになる。線は
  「ある」だけでは足りず、**境界として明示する**：面同士を直接
  触れさせず、すべての領域を線で閉じる。輪郭の小さな凹凸（横顔の
  鼻など）も面の輪郭としてではなく線として描く。線で囲まれた形は
  閾値を超える太さと色差を持つため生き残り、線で囲まれていない
  マーク（点状のパーツ、色面だけの模様）は落ちる。実測：境界を
  明示した描き直しは復旧ゼロで302パス/330KB、明示しなかった同一
  題材は顔の復旧込みで約1,200パス/917KB。
- **影は階調の数ではなく形で情報を運ぶ**。既定はベース＋影1色とし、
  影の形（切り込み、角度のある面）を形に沿って設計する。影を漠然と
  置くと、階調数を減らしても形が崩れる。
- **分離は配色で担保する**。色数を絞り、隣接する部位の明度差を大きく
  取ることで、下流の統合（概念5）が起きない配色にする。

段になった階調は、この文法の例外として使う：濃淡そのものが情報を持つ
絵（概念2）でのみ、部位ごとに階調数を予算化する。逆に、この文法で
描かれた絵は描き直し自体が不要で、直接トレースが最適になる。

### 9. 分離はキー色で設計する

主題と背景の分離は、下流の判定に任せず、描く段階で保証する。
主題に含まれない単一色（キー色）で背景を統一して描かせると、
色距離に依存せず分離が常に決定可能になり、背景親和（近い色同士の
統合）は構造的に起きない。背景は独立した色の集合として残るため、
後段で透明化・色替え・別背景との合成がコードでできる。

- キー色は生成ノイズで近傍の複数色に割れる。キーイングは完全一致
  ではなく色の族で行う。
- 背景モチーフは絵の中では持てなくなる。モチーフは別レイヤーで
  用意し、合成する前提にする。
- 主題自体がキー色の族を含む絵では使えない。その場合は主題に
  無い色を選ぶ。
- 逆に、**主題が背景色を含む絵**（白い服×白背景など）では分離が
  逆向きに壊れる：主題の背景色部分が背景と同一視されて消える。
  この場合の復旧はトレースではなく、ピクセルマスクから主題の
  輪郭を実測抽出して本体を敷き直す。

## 手順

### 1. 分解

元絵について、チャネルごと（概念2）に決める：

- 保持するもの：本人性を担う要素。その性質は測定できる形で書く
  （例：目の虹彩の露出は約◯％、フレーム端で切れた要素は切れたまま、
  表情の癖は文章で）。
- 捨てるもの：本人性を担っていない内部ディテール全般。
- 部位ごとの参照の仕方：コピーさせる部位と、輪郭と色だけ参照させて
  中身を新規に描かせる部位を分ける（概念4の配分の前提）。

支配項の判定（概念3）もここで行う。要素数が支配的なら着手しない。

### 2. 描き直し（画像生成）

`references/redraw-prompt.md` のテンプレートを使い、元絵を添付して生成する。
指定はすべて測定できる単位で書き、保持項目は漏れなく列挙する（概念1）。
様式カテゴリの選択として抽象度を部位ごとに設定する（概念4）。
塗りの目標は概念8の文法（線で境界、影は形、配色で分離）とし、文法と
予算（個数・階調数）は別軸なので両方を指定する。文法だけでは複雑さは
下がらない（実測：文法のみ指定で 475パス、予算併記の中抽象版は 210パス）。
濃淡が情報を持つ絵では、階調を消さず「部位ごとの階調数」として予算化し、
重なりは実色の面で置く（半透明の再現はベクターに翻訳できないため）。

文法は言葉だけでなく**様式参照画像**でも伝えられる。目標の塗りを持つ
絵をもう1枚添付し「この塗りの文法で」と指定すると、影の形や線の扱いが
言葉より正確に移る。ただし参照画像は内容（背景のモチーフ、配色、
小物）も漏れてくるため、漏れが許容できる場合にだけ使う。

参照の使い方は目的で分ける。**軽さ優先**なら単純さの水準だけを参照し、
保持指定は自分の言葉で足す。**質優先**なら強い参照の文法を丸ごと
真似させる：塗りだけでなく顔の扱い（顔は肌1色で影を持たない等）や
表情まで移るが、描き込みも戻るためコストは上がる（実測：同じ題材で
軽さ優先 161パス / 質優先 265パス）。表情まで移すかどうかは保持項目の
指定で決める。

背景の分離が要る絵では、キー色の単色背景で描かせる（概念9）。
背景モチーフが要る場合は、主題をキー色背景で作ってから別レイヤーの
背景と合成する。

### 3. トレース（機械処理）

同梱スクリプトで固定設定トレース＋計測する。設定を固定するのは、
結果を比較可能にするためである：

```bash
pip install vtracer pillow cairosvg   # cairosvg はプレビュー描画用（任意）
python3 scripts/trace_and_measure.py input.png output.svg --render preview.png
```

固定設定：`filter_speckle=16, color_precision=5, layer_difference=24,
corner_threshold=60, length_threshold=6.0, splice_threshold=45,
path_precision=2, mode=spline, colormode=color`

### 4. 検証ゲート

概念6の通り、両方の形で検証する：

- 描き直しラスターの目視：保持項目が全部残っているか、内部ディテールが
  予算内に収まっているか、構図と色の関係が崩れていないか。
- **トレース後SVGのレンダリング目視（必須）**：顔パーツの生存、部位間の
  色の分離、同色レイヤーが境界を越えて氾濫していないか、文字の欠けを
  確認する。ラスターだけ見て合格にしない。
- 計測：元絵の直接トレースと比較し、パス数とバイト数を報告する。
  届かない場合は予算配分（工程1〜2）に戻る。元絵自体が低解像度・低複雑度
  の場合は数値が逆転しうる。そのとき成果はサイズではなく、解像度と
  編集可能性である。

### 5. コード側の調整（トレース後）

概念7の通り、数値で決められる調整は再生成せずコードでやる：

- **色の置換**：fill値を目標RGBへ直接置換する。部位間の関係（概念5）を
  見ながら寄せる。生成の色ブレ（特に肌色）は、参照と成果物で同じ部位
  （頬など）の中央値を実測してから直す。ブレは大抵1チャネルの偏り
  なので、ズレたチャネルだけfill群を寄せれば揃う。
- **小パーツの後足し**：閾値で落ちた必須パーツ（鼻の点など）は、
  元絵の実測座標に図形として足す。位置は必ず元絵で実測する
  （目測は数十px単位で外れる）。パーツには色だけでなく大きさの
  上限もある：鼻の点は顔幅の約2％を超えると「点」ではなく「影」
  として読まれる。点の色は線画色が基準で、肌の影色で置くと影に
  化けやすく、彩度の高い色では別の記号（赤鼻等）に化ける。
- **文字の活字化**：文字を含む絵では、吹き出し等の内側を無地にしてから
  トレースし、文字列を `<text>` 要素として実測位置に置く（概念2）。
- **トーンパターン**：ベタ面を `<pattern>` のドット塗りに差し替えると、
  パスを増やさずに濃淡をパラメータとして足せる。
- **補修の規律**：マスクと活字のハイブリッド補修を重ねて汚れたら、
  パッチを足さず、ベースのSVGから組み直す。

## 到達点

このスキルの成果物は「トレース可能なフラット絵」と「計測・検証済みの
SVG」まで。トレース結果はアンカーの羅列であり、部品化・名前付けなどの
コードベースへの組み込みは別工程である。

変換の実例（before/after画像）は `examples/` フォルダとリポジトリの
READMEに置いてある。文言の説明より先にそちらで形を確認する。
